# Phase 2 - Foundation and Standalone Targets

## Status

Build conversion is complete for Debug and Release on x64 and the maintained
Win32 standalone subset. Deterministic functional verification remains open
under the current phase-local behavioral gate.

## Scope

Phase 2 converted:

- CommonUtilities base library.
- PresentData library.
- Metrics library split from CommonUtilities.
- PresentMon standalone console.
- Intel PresentMon ETW provider DLL.
- ETLTrimmer.
- `etw_list`.
- `pm_convert_csv`.

No source files were moved or modified.

## Foundation Split

The MSBuild `CommonUtilities` project contained a source-level dependency cycle:

```text
PresentData -> CommonUtilities
CommonUtilities/mc -> PresentData
```

CMake now represents the acyclic graph:

```text
pmon_common_utilities -> pmon_present_data -> pmon_metrics
```

`pmon_common_utilities` contains all legacy CommonUtilities compilation units except `mc/*.cpp`. `pmon_metrics` owns the ten metric-calculation compilation units and links both foundation dependencies.

The existing headers still require the repository root as a public include directory. Narrower installed and build-interface include boundaries remain deferred until source headers are reorganized.

## Dependency Contract

CommonUtilities exposes its public header dependencies:

- Boost.Asio
- cereal
- CLI11
- concurrentqueue
- WinReg headers

Windows libraries are declared explicitly instead of relying only on source pragmas or executable link lists. PresentData carries its ETW dependencies on `advapi32` and `tdh`. ETLTrimmer explicitly links its COM and automation dependencies.

Static CRT selection, warning levels, exception handling, Unicode definitions, C++ language mode, and control-flow guard behavior preserve the relevant MSBuild settings.

## Generated Files

The version header is generated by CMake at:

```text
build/obj/generated/version.h
```

For fixed release versions it contains the version from `Version.props`. For `PresentMonVersion=dev`, CMake records the Git branch and commit when available.

The Windows SDK message compiler now generates resources in the build tree for:

- `PresentMon/ddETWExternal.xml`
- `Provider/Intel-PresentMon.man`

Unlike MSBuild, the PresentMon message resource generation works for both x64 and Win32.

## Output Contract

x64 outputs:

```text
build/<Configuration>/PresentMon-2.6.0-x64.exe
build/<Configuration>/Intel-PresentMon.dll
build/<Configuration>/ETLTrimmer.exe
build/<Configuration>/etw_list-2.6.0-x64.exe
build/<Configuration>/pm_convert_csv.exe
build/<Configuration>/PresentData.lib
build/lib/CommonUtilities-x64-<Configuration>/IPMCommonUtilities.lib
```

Win32 outputs:

```text
build/<Configuration>/PresentMon-2.6.0-x86.exe
build/<Configuration>/Intel-PresentMon32.dll
build/<Configuration>/etw_list-2.6.0-x86.exe
build/<Configuration>/pm_convert_csv.exe
build/<Configuration>/PresentData.lib
build/lib/CommonUtilities-Win32-<Configuration>/IPMCommonUtilities.lib
```

ETLTrimmer remains x64-only.

PresentData, Metrics, and `pm_convert_csv` use architecture-qualified internal output directories. Post-build copies preserve the legacy unqualified public paths. This prevents incremental x64 and Win32 builds from consuming a binary produced for the other architecture.

## Vcpkg Architecture Isolation

The vcpkg target triplet is selected from the CMake generator platform:

- x64 uses `x64-windows-static`.
- Win32 uses `x86-windows-static`.

Each target triplet has a separate manifest installation root under:

```text
build/ThirdParty/vcpkg_installed/<triplet>/
```

This is required because vcpkg manifest reconciliation can remove packages for a different target triplet when both architectures share one installation root. Downloads remain shared under `build/ThirdParty/vcpkg-downloads`.

## Verification

Build verification succeeded for:

```powershell
cmake --preset windows-x64-dependencies
cmake --preset windows-x64-developer
cmake --build --preset windows-x64-developer-debug
cmake --build --preset windows-x64-developer-release

cmake --preset windows-win32-dependencies
cmake --preset windows-win32-developer
cmake --build --preset windows-win32-developer-debug
cmake --build --preset windows-win32-developer-release
```

Runtime smoke checks:

- x64 and Win32 PresentMon consoles printed version `2.6.0` and usage.
- ETLTrimmer printed help and exited successfully.
- `etw_list` printed its expected usage and build version.
- `pm_convert_csv` printed its expected no-input usage.
- Both provider DLLs report file and product version `2.6.0.0`.
- Provider original filenames correctly distinguish `Intel-PresentMon.dll` and `Intel-PresentMon32.dll`.

PresentMon, `etw_list`, and `pm_convert_csv` intentionally return a nonzero status for the tested help or missing-argument paths; their expected output was produced.

These checks cover startup and argument handling, but they do not exercise a
representative functional workflow. A deterministic Phase 2 behavioral workflow
must be added before full migration parity is declared.
